2026-10-15 15:53〜15:55 JST、検証用AWSプロファイル の検証用アカウント・東京（ap-northeast-1）で検証しました。検証リソースはすべて削除済みです。

Node.js 24から起動したStaticPHP製FrankenPHPが、AWS指定アドレス `0.0.0.0:3000` を直接待ち受け、HTTPS経由のリクエストをPHPで処理できました。Node側にHTTPプロキシはありません。バイナリ・アプリの変更なしで、前回生成済みの `dist/package` を使用しています。

## コストを抑えた設定

- HomeRegionで東京のみ。IAM認証を使用し、匿名からの実行を防止。
- 環境数上限2（AWSの最小値）、環境あたり同時リクエスト1、リクエストタイムアウト5秒。
- AWSの受付レート上限100/秒（最小の非ゼロ値）。検証クライアントは約1秒間隔で6回だけ送信。
- 専用S3バケット・ログ書き込みだけの専用IAMロールを使用。ログ保持1日を設定したうえで、取得後に削除。
- NAT Gateway、VPC、CloudFront、独自KMSキー、Provisioned Concurrencyは作成していません。
- 成功した検証の準備開始から後片付け完了まで約56秒。確定請求額は未取得です。

AWSのメモリ課金にはリクエスト間の環境存続時間も含まれるため、検証後すぐに削除しました。[公式料金](https://aws.amazon.com/lambda/pricing/)参照。S3/API操作・ログの少量課金もあり、無料であるとは断定していません。

最初の試行は `maxEnvironments=1` がCLIに拒否され、Web Function作成前に停止しました。S3・IAM・ログの作成分は削除済みです。実際の下限はCLIの詳細仕様で再確認し、2回目に成功しました。
